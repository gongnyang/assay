## 1. 시작 전 확인

S3에는 아래가 모두 있어야 한다.

- `reach-gate.sh`가 exit 0으로 sources·anchors를 수납했다.
- `bench-init.sh`가 만든 `gate.conf`가 있고, 축·합격선·readonly·승격값이 이미 봉인됐다.
- `rubric-lint.sh`가 exit 0이다. `rubric.md`의 축과 aid를 다시 해석하지 않는다.
- 자동검증 축의 `metrics/*.tsv`가 최신이고, 대상 수정 전 상태와 연결된다.

어느 하나라도 없으면 채점을 시작하지 않는다. 빈 앵커 파일이나 말뿐인 계측으로 BASE를 기록하는 것은 "무측정 만점"의 다른 형태다.

## 2. 계측기 선택

계측기는 점수를 직접 정하지 않고, 자동검증 전제의 원시 수치를 TSV로 낸다. 정성 축은 aid 인용과 G2 독립 채점에 의존한다.

| 대상 | 동봉 계측기 | 역할 |
|---|---|---|
| 스킬 디렉터리 | `measure-skill.sh <skill-dir> <run-dir>` | 구조·로드경제성·실행 표면을 계측하고 봉인 임계와 대조 |
| Git 저장소 | `measure-repo.sh <repo-dir> <run-dir>` | M1~M18 전제와 채점 입력을 TSV로 산출 |
| 그 밖의 대상 | 새 계측기 | [instruments.md](instruments.md)의 TSV·exit 계약을 구현 |

정성 축이 전체의 과반이면 규모와 무관하게 G2를 생략하지 않는다. `rubric.md`의 `measure:` 보유 축 비율로 이 조건을 판정한다.

## 3. S3 베이스라인

수정하지 않은 대상을 전 축으로 채점하고, 축마다 현재 점수의 aid·실측 근거를 `<run>/anchors/R0.md`에 남긴다. 다음을 실행한다.

```bash
bench-log.sh <run> R0 - <축별점수csv> "베이스라인"
```

`bench-log.sh`는 min, sum, 판정식 결과, verdict를 계산해 `scores.tsv`와 `rounds.jsonl`에 함께 append한다. BASE도 성공·실패 이력을 숨기지 않는 라운드다.

앵커 파일에는 축 ID마다 한 줄이 있어야 한다. 인정되는 증거는 `R-` 소스 ID, `[실측]`, 유니코드 파일명을 포함할 수 있는 `<파일>.<확장자>:<줄>`, 직접 인용이다. 검사는 Python 유니코드 문자열 대조로 한다. 영문 문자 클래스만 허용하는 정규식으로 한글 파일명을 반려하지 않는다.

## 4. S4 개선 라운드

각 라운드는 하나의 최저 축을 겨냥한다. 동점이면 자동검증 축을 먼저, 그다음 앵커가 가장 선명한 축을 택한다.

```text
Rn
1. 직전 KEEP/BASE 상태를 보존한다.
2. 최저 축 하나만 목표로 수정한다.
3. 계측기를 다시 실행하고 전 축을 재채점한다.
4. Rn 앵커 파일을 축별 근거와 함께 쓴다.
5. bench-log.sh로 판정을 기록한다.
6. REVERT면 즉시 bench-revert.sh를 실행한다.
```

한 라운드에서 여러 축을 동시에 고치면 원인과 효과가 섞인다. readonly 범위는 개선 대상이 아니다. BASE가 이미 PASS이면 루프를 열지 않고 G 단계로 간다.

## 5. 파레토·단순화·되돌림

판정은 사람이 선언하지 않는다.

| 조건 | verdict | 행동 |
|---|---|---|
| 첫 기록 | `BASE` | 기준 상태로 보존 |
| 어떤 축도 하락하지 않고 총점 상승 | `KEEP` | 새 기준 상태로 채택 |
| 한 축이라도 하락 | `REVERT` | 즉시 직전 KEEP/BASE로 복원 |
| 전 축 동일·총점 동일·복잡도 감소 증명 | `SIMPLIFY` | KEEP과 동등하게 채택 |
| 전 축 동일이나 복잡도 증거 없음 | `REVERT` | 복원 |

`--simplify`는 우회가 아니다. 행수·파일 수·의존성 수 중 해당 복잡도 계측값이 `metrics/`에서 실제로 감소했음을 보여야 한다. 증거 없는 플래그는 exit 2다.

`bench-revert.sh <run> <round>`는 git 대상이면 봉인된 커밋·트리 해시로, 비git 대상이면 `rounds/<round>/` 스냅샷과 파일별 SHA-256으로 복원한다. 복원 해시가 직전 KEEP/BASE와 다르면 exit 1, 복원 대상이 없으면 exit 2다. 직전 라운드가 REVERT인데 복원 증거가 없으면 다음 `bench-log.sh`는 exit 2로 기록을 거부한다.

## 6. 로그 계약

`scores.tsv`는 사람이 빠르게 읽는 표다. 축 수는 gate.conf의 `AXES`에 고정되며, 라운드마다 정확히 한 행을 남긴다.

```text
round  axis  A1  A2  A3  min  sum  gate  verdict  note
R0     -     2   3   1   1    6    FAIL  BASE     베이스라인
R1     A3    2   3   3   2    8    FAIL  KEEP     aid 보강
R2     A1    1   3   3   1    7    FAIL  REVERT   A1 하락
```

`rounds.jsonl`은 기계 판정 이력이다. 각 객체에는 `round`, `ts`, `axis`, `axes`, 축별 점수 리스트 `scores`, `min`, `sum`, `max`, `gate`, `verdict`, `delta`, `note`, `prev_hash`, `self_hash`(+조건부 `complexity`/`state`)를 남긴다. REVERT·크래시·SIMPLIFY를 빼지 않는다.

점수 숫자만 손으로 채워도 기록은 유효하지 않다. 자동검증은 TSV 셀과, 정성 축은 앵커 파일의 실물 인용과 연결되어야 한다. `bench-log.sh`는 누락을 exit 2로 막는다.

## 7. 정체와 종료

연속 3회 REVERT면 결과물을 계속 고치지 말고 STOP(진단)으로 닫는다. 다음 순서로 의심한다.

1. 축이 대상의 통제 밖인가. 그렇다면 전제 또는 리스크로 내린다.
2. 같은 물건의 점수가 흔들릴 만큼 aid가 모호한가. 앵커를 보강한다.
3. 레퍼런스도 도달하지 못하는 축인가. 합격선을 내리지 말고 축·앵커를 고친다.
4. 소비처·readonly 같은 R0/S0 전제가 틀렸는가. 새 런에서 다시 봉인한다.

진단은 `STALL` 행으로 기록한다. 루브릭이 바뀌면 이전 점수와 비교하지 않으며 R0부터 재채점한다. 종료 상태는 PASS, STOP(진단), STOP(범위) 셋뿐이다. "계속 돌리는 중"은 상태가 아니다.

## 8. 독립 채점과 하한

본격 규모는 G1 뒤 G2·G3를 모두 수행한다. G2는 `g2-spawn.sh`가 루브릭과 대상 스냅샷만 독립 워커에게 주고 회수한다. 개선 내역·자기 점수·기존 앵커 파일은 전달하지 않는다.

- 2점 이상 차이면 결과물이 아니라 그 축의 aid를 보강하고 exit 1로 돌아간다.
- 1점 차이면 낮은 점수를 `scores.tsv`에 채택한다.
- 인용을 못 대는 축은 점수가 아니라 판정 불가다.

G3의 `verdict-gate.sh`는 반례, 역방향 채점, 점수 균질성, 미검증 축을 검사한다. PASS 문자열은 이 마지막 경로만 출력한다.
